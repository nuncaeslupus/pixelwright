▸Technical solution

▸Architecture overview

Three layers, one flow (spec §2.2):

  • Core (Python library + pw) owns every file in a project: the project, group and asset files, versions, the advice log, normalising, checks, export and pw wait. Everything an AI or the app does goes through it.
  • App is a pywebview window started by pw open. The page is plain HTML/JS/CSS, as today. It calls the core in-process through pywebview's js_api, so there is no HTTP server, port or token. It has two screens: Project (assets by group, each with its state and next step) and Asset (the image in the centre, a strip of versions, before/after, advice on the image, and the actions accept, reject, request, star, approve and open in Aseprite).
  • Agent instructions: Claude skills for steps 0 and 4 and for the bridge, plus AGENTS.md for other agents.

▸Data flow

Person or AI → pw add (inputs) → pw normalize (v001) → pw check (script advice) → AI loop via pw advice / fix ops (ai advice, new versions) → app (person accepts or rejects, or leaves a request) → pw wait wakes the AI → … → pw approve (final + export).

▸Technology choices

Choice Justification
pywebview (≥ 5) Native window from Python, reuses the HTML/JS UI, runs on Linux (WebKitGTK) and Windows (WebView2) (D-10)
tomllib + tomli-w TOML for every human-readable file (spec criterion: plain png/toml/jsonl)
Polling in pw wait (1 s) Portable across Linux and Windows; inotify is not needed at this scale

▸Out of scope

  • Delta storage of versions (D-13)

  • New check rules or providers
