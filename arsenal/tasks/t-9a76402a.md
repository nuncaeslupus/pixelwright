The first run in `docs/guide/comfyui.md` is
`pw snap hill && pw quantize hill && pw clean hill && pw check hill`. From a
workspace made by `pw init` + `pw new`, quantize stops there:

```
{"ok": false, "command": "quantize", "error": {"code": "no_palette",
 "message": "no palette: pass --palette, --discover or set one on `new`"}}
```

and `clean` then fails as a cascade (`not_indexed`). `pw init` writes no
default palette and `pw new` sets none, so the documented chain can never run
as written. Measured on a real ComfyUI run, 2026-11-15.

Decision: make `pw quantize` discover a palette when the asset has none,
emitting a warning that names the colour count it chose, rather than erroring.
That keeps the documented chain true and is a smaller change than teaching
`pw init` to ship a palette. If a silent discovery is judged too surprising,
the alternative is `pw new` writing a default palette — in which case fix the
guide instead and close this with that test.

## Tests
A test in `tests/core/test_quantize.py` that runs the documented chain
(`new` → `attach` → `snap` → `quantize` → `clean` → `check`) on a fixture with
no palette anywhere and asserts every step exits 0.
